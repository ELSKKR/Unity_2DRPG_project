# 決策表單

## 什麼時候用

兩種情境撐得起一個表單的成本：

1. **效果類決策難用形容詞講清楚**——「變暗」「常駐」「半透明」這種詞，我跟使用者腦內的畫面不一定一樣。與其寫五段文字描述五種效果，不如做五張可以實際滑一下、按一下的卡片，讓對方直接感受差異。
2. **要對一堆項目做批次是非決策**——例如「場景裡這 20 顆按鈕，你要哪幾顆套用」。文字列清單使用者要逐行對照，checkbox 一目瞭然，还能整組全選/取消。

單純「A 還是 B」的二選一，或選項用一句話就講得清楚，**直接用 AskUserQuestion**，不要做表單——多一輪 Artifact 發布只會拖慢，沒有多賺到清晰度。

## 結構（三段式，缺一段都會變得難用）

1. **效果демо區**：真的可以互動（hover / mousedown 有反應），不是放幾張靜態截圖。能用實際素材（游戏内的 sprite、颜色、字体）就不要用 CSS 憑空畫近似值——這次示範按鈕直接把遊戲內真正的四角框 PNG 當 Artifact 的 `files` 傳進去疊在示意按鈕上，使用者一眼就認出跟遊戲裡是同一個東西，如果只用 CSS 隨便畫幾條線，使用者沒辦法信任「這就是套用後的樣子」。
2. **批次清單區**：分組、每組一個「全選/取消整組」的 checkbox、每個項目帶清楚的識別資訊（不只是名字，還要有能對到實體的路徑/位置）。預設值要反映現狀（已經做過的打勾、明顯不該碰的不打勾並註明原因），不要全部留白讓使用者從零開始想。
3. **送出**：呼叫 Artifact 全域的 `sendPrompt(text)` 把整理好的結果送回對話。**這一段最容易犯錯，見下面的坑**。

## 踩過的坑

- **送出按鈕不要用 `disabled` 卡住流程。** 第一版把按鈕設成「必須先選一個效果才能點」，使用者只勾了下面的清單、沒點效果卡片，按鈕就是死的——使用者的反饋是「按了沒反應」，因為 disabled 元素本來就不會觸發任何事件，畫面上也看不出「為什麼」。改法：按鈕永遠可點，沒滿足條件時用一個明顯的提示（文字 + 輕微震動動畫）告訴使用者少了什麼，不要用「按不下去」來傳達。
- **`sendPrompt` 可能不存在或失敗，一定要有保底。** 不管送出是否成功，都要把整理好的文字顯示在畫面上（一個 `<textarea readonly>` + 複製按鈕），這樣就算自動送出失敗，使用者手動複製貼上也能完成任務。用 `try/catch` 包住 `sendPrompt` 呼叫，永遠不要讓失敗變成靜默的「什麼都沒發生」。
- **「玩過」要等於「選了」。** 效果卡片如果只在真的點擊卡片本身（例如卡片右上角一個小 radio）才算選中，使用者滑過示範按鈕本身試效果、以為自己已經選了，其實沒有。讓示範按鈕的 `mouseenter`/`mousedown` 也順便觸發選取，別逼使用者做兩次動作。
- **按鈕清單要用真資料，不要編。** 如果是遊戲/App 場景裡的元件清單，先實際掃描（Unity 的話用 MCP `eval` 跑 `Resources.FindObjectsOfTypeAll<Button>()` 之類），列出真實的名稱和階層路徑；順手把不屬於目前討論範圍的東西（舊版面板、已棄用的頁面）分組標註出來並預設不勾，好過假裝它們不存在。

## 發布時的 Artifact 工具細節

- `intent: "other"`（quickstart）——這種互動表單不是 document/slides/design，走 plain page。
- 要嵌真實素材：發布時用 `files` 參數把本地檔案（PNG、素材圖）一併帶上，HTML 裡用相對路徑直接引用（`url("corner_l.png")`），不用 data URI 轉來轉去。
- 使用者要求修改時，用同一個 `url` republish 保留連結，不要重新發布出一個新網址——每次要求「怎麼還是舊的」通常代表忘了帶 `url`。
- 頁面本身照一般 Artifact 設計規範（響應式、深淺主題都要撐住），但這類工具型頁面不需要花俏視覺，清楚可操作優先於好看。

## 最小骨架

```html
<title>...</title>
<style>
  /* demo-card：可互動示範，radio 選取狀態 */
  /* group / row：分組 checkbox 清單，group 帶「全選」toggle */
  /* .result：送出後一定顯示的文字保底區，不是 alert */
</style>

<div id="demoGrid"></div>   <!-- 效果卡片，JS 動態產生 -->
<div id="groups"></div>     <!-- 分組清單，JS 動態產生，資料寫成 JS 陣列方便之後擴充 -->

<div class="result" id="resultBox" hidden>
  <textarea id="resultText" readonly></textarea>
  <button id="copyBtn">複製文字</button>
</div>
<button id="submitBtn">送出</button>  <!-- 永遠可點，不要 disabled -->

<script>
  // submitBtn.click: 沒選效果就提示 + 震動，不要 return 什麼都不做
  // 選好了：組字串 → resultText.value = msg; resultBox.hidden = false
  //         try { sendPrompt(msg) } catch {} —— 不管成不成功，文字保底都要留著
</script>
```
