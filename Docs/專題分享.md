# 林溪村 —— 專題分享

## 專題簡介

我的作品是一款 Unity 2D 像素風俯視角 RPG，個人開發。目前有 71 支 C# 腳本、7 個遊戲場景，玩家在村莊裡探索、跟 NPC 對話、接任務、蒐集情報。

## 選題理由

除了本身就喜歡玩以外，做 RPG 是因為系統多、互相牽連——存檔、任務、對話、世界狀態全部要串起來，很適合拿來練遊戲架構。

分工模式也是刻意選的：程式邏輯、debug 全部交給 Claude Code 處理；我自己專注在視覺美術判斷、關卡佈局、音效選擇，系統架構則是跟 Claude Code 討論後一起拍板。透過這個專題，我能學習到最近流行的 vibe coding。

## 遇到的困難與怎麼解決

### 困難一：場景架構——換地圖時哪些東西該活下來

**問題**：玩家切換場景時，角色、UI 會被新場景蓋掉。專案最早的版本就是這樣，走進房子會發現背包空了、任務不見了、玩家角色重新出現在地圖原點。

**第一次嘗試**：Unity 內建的 `DontDestroyOnLoad`，標記物件「換場景時不要銷毀我」。看起來剛好解決問題，但實務上很難維護——每個要保留的物件都得記得標記，漏掉一個就是某功能莫名其妙失效，而且不會報錯；回標題畫面時還要手動一個個銷毀，一樣容易漏。它能動，但把維護成本轉嫁到「人要記得」上面。

**最後解法**：改成兩層結構。下層 `Persistent` 場景永遠載入、永不卸載，放玩家角色、攝影機、所有管理器、整個 UI 畫布；上層是村莊、四間室內、標題畫面等關卡場景，用「加法式載入」疊在 Persistent 上面——載入新場景但不清掉舊的。進出房子只卸載上層，下層動都不動。漏標記這種問題從結構上就不存在了。

### 困難二：與 Claude Code 合作面臨的挑戰

- **AI 做出來的和自己想的不一樣怎麼辦** 靠的是輸入prompt前就把架構想清楚，目標、背景、素材、邊界、完成定義，此外也可以使用 skill 或 claude.md  來輔助。
- **AI 會不會自作主張改到我的東西？** 真的發生過——Play Mode 測試時銷毀了一個場景物件，結果被寫回場景檔，永久遺失，得手動重建。這之後訂了規則：會動到既有內容的操作一定要先講清楚，測試用的物件要另外建、測完就刪，不能拿正式場景物件冒險。
- **AI 難免會出錯，如何風險管理？** 有次想把標題畫面、存檔介面全部換成新的 UI 素材包風格，結果做壞了，最後只能整個撤銷重來。學到的是：做好版本控制：在做這種牽動既有東西的改動前，要先 commit，不然做完才發現方向錯了就回不去了。
