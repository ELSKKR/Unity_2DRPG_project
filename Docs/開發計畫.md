# 林溪村 — 後續開發計畫

**方向**：遊戲外觀包裝與功能優化，不做新的劇情內容。
**決定**：UI 全面換成暖棕色素材包／標題用真實場景做動態背景／小地圖做角落即時＋M 鍵大地圖／**小地圖優先**。

**這份計畫是模組化的**——除了階段 0 是所有視覺工作的前置，其餘四塊彼此獨立，順序可以隨時調換，也可以只做其中幾塊。

---

## 階段 0 — 素材包匯入修正（前置，約 10 分鐘）

**這是唯一必須先做的事。** 不修的話後面做出來的 UI 會是糊的，而且你會以為是設計問題。

`Assets/Sprites/UI/PNG/SpriteSheet.png`（704×2160，已切好 133 個 sprite）：

| 問題 | 現況 | 改成 |
|---|---|---|
| `maxTextureSize` | **2048，但圖高 2160** → Unity 縮到 0.948 倍，非整數縮放毀掉像素對齊 | 4096 |
| Standalone 壓縮 | `textureCompression: 1` | None（專案鐵則） |

`filterMode: Point` 已經是對的。

**驗證**：改完讀回貼圖實際尺寸，確認是 704×2160 而不是被縮過的數字；隨便挑一個面板 sprite 放大看邊緣有沒有半透明過渡像素。

## 階段 1 — 小地圖（你最在意的，先做）

### 設計：一台相機、一張 RenderTexture、兩種模式

不做兩套系統。角落小地圖和全螢幕大地圖**共用同一台 minimap 相機**，切換時只改三件事：正交尺寸、相機位置、RawImage 的大小與位置。

| | 角落模式 | 大地圖模式 |
|---|---|---|
| 正交尺寸 | 小（約 12，看得到周圍一圈） | 大（約 45，涵蓋整張地圖） |
| 相機位置 | 跟著玩家 | 固定在地圖中心 |
| RawImage | 右上角，配素材包的圓框/方框 | 接近全螢幕 |
| 更新頻率 | 每幀 | **打開時算一次就好** |

### 關鍵決定：不重新分層

原本擔心 2509 個草花、292 顆石頭在小尺度下會變成雜訊，需要把三千多個物件重新分層才能篩掉。**但你那張 `全地圖.png` 已經證明不用**——所有雜物在縮小後反而構成好看的地表紋理，密林邊界、S 形河、四棟房子、中央廣場的辨識度都很高。

所以 culling mask 只要排除 `UI` 層就好，**零重新分層工作**。這省掉了這個階段最大的一塊成本。

### 要做的事

1. **`KeyBindings` 加 `ToggleMap`**（4 行：enum、Defaults 給 `KeyCode.M`、`RebindableActions` 加上標籤「地圖」）。因為鍵位設定畫面是照 `RebindableActions` 跑迴圈的，**加完設定畫面會自動長出這一列**，不用改 UI——這是你「抽象層要在需要之前先做」原則的直接回報。
2. **minimap 相機 + RenderTexture**，放在 `Persistent`（跟其他常駐系統一致）。
3. **玩家標記**：素材包裡有現成箭頭。世界座標 → RawImage 上的 UV 換算，角落模式標記固定在中心、大地圖模式標記隨玩家移動。
4. **大地圖實作 `IMenuPanel` 並接 `UIPanelManager`**——這樣才會自動遵守「對話中不能開選單」以及 Esc 關閉的既有規則，不用自己重寫一套。
5. **框與底**：用素材包的面板框。

### 待決定的細節（做到再問你）

- **進室內時小地圖怎麼辦**：房子很小，選項是「隱藏」或「顯示房間平面」。預設先做隱藏，最省。
- **要不要放 NPC／任務目標標記**：可以但屬於加分項，建議第一版先不做，確認基本的好用再加。
- **要不要迷霧（未探索區遮住）**：村莊不大，全部可見可能比較舒服。第一版先全可見。

### 驗證

- 玩家走到地圖四個角落，標記位置跟實際世界座標的誤差要能算出數字，不是「看起來對」。
- 大地圖模式截圖跟 `全地圖.png` 疊比對，確認涵蓋範圍完整、沒有切掉邊界。
- 開對話時按 M 應該打不開（`UIPanelManager` 規則生效）。

## 階段 2 — 標題畫面動態背景

### 為什麼順路

現在的開機流程是 `Persistent` → 關閉玩家 → **加法式**載入 `TitleScreen`。要讓村莊當背景，只是在同一個地方**再加法式載入 `Forest_Village`**，架構上完全順著現有做法，不是新機制。

**附帶好處**：按下「開始遊戲」時村莊已經在記憶體裡，省掉載入空窗。等於把載入時間從「按開始之後」搬到「開機時」，總量沒變但體感更好。

### 要做的事

1. `BootstrapLoader` 多載入一個 `Forest_Village`。
2. 相機在標題模式走一段緩慢平移（或定在一個好看的角度）——需要一個標題模式接管 `CameraFollowSmooth`。
3. 玩家維持關閉（**現況已經是這樣**，不用改）。
4. 選好取景點：河邊、廣場、或黃昏感的屋舍。這個要你挑，我做幾個角度截圖給你選。

### 風險（都要實測，不能假設）

- `CameraFollowSmooth` 與 `CameraBounds` 會不會跟標題平移打架。
- `SceneTransitionManager.SetCurrentSceneWithoutSpawn(titleScene)` 現在同時有兩個場景載入，「目前場景」的語意要確認不會影響之後的存檔定位。
- 村莊的環境音會在標題就開始播——可能是特色，也可能很吵，要聽過再決定。
- 開機時間會變長，要實測秒數。

## 階段 3 — UI 素材包全面套用（最大的一塊）

### 前置工時：9-slice 邊界

133 個 sprite 已經切好，但面板和按鈕**還需要逐一設定 border 值**，否則拉伸時邊框會變形。這是這個階段的主要工時，不是「換張圖」那麼簡單。只有面板/按鈕/框需要，圖示類不用。

### 建議順序（每做完一個就看得到成果，可以隨時喊停）

1. **對話框** — 玩家看最久的東西，改完感受最明顯。素材包有專門的對話框（含尖角尾巴）與 mini 版。
2. **背包／任務／情報** — 三個分頁共用同一套框。順便解決背包右邊那片空白（見階段 4）。
3. **設定畫面** — 素材包直接附了 `DISPLAY / AUDIO / VIDEO / CONTROLS` 分頁標籤、核取方塊、滑桿。
4. **存檔槽** — 現在是最原型的一塊。
5. **標題按鈕** — 五種尺寸按鈕現成。

### 一個容易忽略的連帶問題

素材包是**暖棕底**，現在的文字是**白色**。白字在暖棕底上會很難讀，全部要改成深褐色系。現有的 Silver／Cubic 像素字型本身跟素材包是搭的，字型不用換，只有顏色要調。

> **提醒**：改字型顏色會連動到 `FontBaselineAligner` 那套 fallback 縮放邏輯嗎？不會（那是字級不是顏色），但改的時候順手確認一下對話框換框之後基線還是對的。

## 階段 4 — 現有小瑕疵

這些都很小，可以隨時插隊做：

1. **存檔槽顯示 `Forest_Village`** — 給玩家看內部場景名。需要一張「場景名 → 顯示名」的對應表（`Forest_Village` → 林溪村、`House_Interior_A` → 愛拉家…）。放哪裡要想一下，`GameDatabase` 是合理的位置。
2. **背包右側約 60% 是空的暗區** — 看起來原本就打算放道具詳情。補上：道具名稱、描述、放大的圖示。素材包有現成的詳情框。
3. **背包裡那個半透明人形** — 截圖裡格子 5 附近有一個半透明角色圖，不確定是刻意的裝備預覽佔位還是穿透的 bug，要查清楚。
4. **存檔縮圖**（加分項）— 存檔時截一張小圖存起來，存檔槽顯示縮圖。要改存檔格式，屬於中型工作不是小瑕疵，看你要不要。

## 排程建議

```
階段 0（前置，10 分鐘）
   ↓
階段 1 小地圖 ←── 你最在意的，先做
   ↓
階段 2 標題動態背景 ←── 獨立，也可以跟階段 3 對調
   ↓
階段 3 UI 套用 ←── 最大塊，建議分多次做，一次一個面板
   ↓
階段 4 小瑕疵 ←── 隨時可插隊
```

階段 1／2／3／4 **彼此不相依**，順序可以隨時改。唯一的硬性順序是階段 0 要在 1、2、3 之前（因為它們都會用到素材包）。

## 貫穿全程的規矩

- **驗證要給數字**，不要「應該可以了」。空間性的東西（小地圖座標換算、UI 有沒有重疊）用計算不用肉眼。
- **Play Mode 絕不對真實場景物件呼叫破壞性方法**——要測就臨時建物件，測完 `DestroyImmediate`。
- **美術判斷給選項讓你挑**：取景角度、框的樣式、配色，我做並排截圖你選，不自己決定。
- **音效只掛空欄位**，不預先指定檔案。
- 每個階段做完，照 `系統開發歷程.md` 的模板（問題→設計→踩過的坑→怎麼驗證）補一節進去。
